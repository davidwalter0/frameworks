* Intentional divergences from the kit (added 2026-08-07)

The tranche-0 contract was a byte-identical copy, and that contract has now
been *deliberately* broken in three files. Each is listed with the reason, so
the next re-sync reconciles rather than reverts. A divergence that is not
written down is indistinguishable from drift.

** =lib/= — still byte-identical, keep it that way
=diff -rq= against kit =lib/= is empty and should stay empty. Everything below
concerns the non-source files copied alongside it.

** =analysis_options.yaml= — DO NOT re-sync the =exclude:= block
Kit commit =cb2bd98= added an =exclude:= block to its own
=analysis_options.yaml=. It exists because the KIT REPOSITORY contains
untracked symlinks to four sibling repos, and =flutter analyze= follows
symlinks — so without the exclusion the kit's gate reported on five projects
and attributed all of it to the kit (11,156 errors from siblings on
2026-08-01, per that commit's own message).

=ui/pkg/desktop_kit= has *zero* symlinks (verified: =find -maxdepth 1 -type l=
returns none). The block is therefore inert here, and copying it would import
a workaround for a problem this location does not have. Left out on purpose.

If the frameworks copy ever gains sibling symlinks, revisit — but the fix then
is to not add the symlinks.

** =Makefile= — dead and BROKEN targets removed
As copied, =check= depended on =analyze-example=, =test-example= and
=orgsupport-check=, which =cd example= and =$(MAKE) -C tools/orgsupport=.
Neither directory was copied (both were excluded from tranche 0 by design), so
the target did not merely reference dead paths — it FAILED on a missing
directory for anyone who ran it. Upstream has since retired =example/= outright
(kit =936e0bf=), so this is not a divergence that will need reconciling.

The package Makefile no longer defines =check= at all. =frameworks/ui/Makefile=
is the single gate; two gates that can disagree is worse than one.

** =vuln= / =deps-guard= — moved UP, not deleted
Both existed in the kit's Makefile and *neither survived the copy* — so from
tranche 0 until 2026-08-07 the Dart half of frameworks had no dependency guard
and no vulnerability stage at all. That was a capability regression introduced
by the move itself rather than by any code change, and it is exactly the class
of loss a "verbatim copy" is assumed to make impossible.

They now live once in =frameworks/ui/Makefile= and run over every package:
- =deps-guard= is the kit's grep verbatim, but scoped via =AGNOSTIC_PACKAGES=
  so the app-shell tier (=ui/pkg/app_kit=, not yet built) can carry Riverpod by
  design without the guard having to be deleted. Whether the guard should be
  *inverted* to require Riverpod 3 is mgmt todo =bd91e7e9= — a design decision,
  not a copy fix, and deliberately not taken here.
- =vuln= is now gated by =ui/tools/osv-gate.sh=. The kit's version ran
  =osv-scanner --lockfile=pubspec.lock || true=; the =|| true= made it a
  reporter that could not fail. The replacement fails on findings that are at
  or above CVSS 7.0 AND have a fix available, and reports the rest.
